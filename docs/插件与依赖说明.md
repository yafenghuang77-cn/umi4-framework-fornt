这里的“插件”包括业务组件库、工具库、Umi 插件和开发工具。声明了依赖不代表已经完成业务接入；图片上传、文档保存、实时通知等仍需配置接口和页面逻辑。

## 二、请求、表单与数据校验

| 依赖 | 用途 | 本项目的使用场景 |
| --- | --- | --- |
| `@tanstack/react-query` | 管理服务端数据的查询、缓存、失效、重新获取和更新状态 | 用户列表、权限资源、系统配置接口；配合 Umi request 使用 |
| `react-hook-form` | 管理表单值、校验和提交状态 | 自定义复杂表单；普通后台表单可优先使用 Ant Design Form / ProForm |

React Query 负责数据缓存和请求状态，Umi request 负责实际 HTTP 请求；两者可以配合。Socket.IO 使用自己的协议，不能直接当作普通 WebSocket 客户端连接任意 WebSocket 服务。

### React Query 全局配置

`config/config.ts` 开启 Umi 的全局 QueryClient Provider，运行时策略通过 `src/app.tsx` 的 `reactQuery` 导出配置。使用项目安装的 TanStack Query v5，不需要在业务页面重复创建 Provider。当前未安装同版本 Devtools，配置中显式关闭调试面板。

| 配置 | 默认值 | 行为 |
| --- | --- | --- |
| `staleTime` | 1 分钟 | 数据在新鲜期内可复用，避免挂载等事件重复获取 |
| `gcTime` | 5 分钟 | 查询没有订阅者后，保留缓存的时间；不是定时刷新间隔 |
| `refetchOnWindowFocus` | `false` | 切换窗口或浏览器标签页不会自动刷新 |
| `refetchOnMount` | `true` | 挂载时自动重新获取已过期的查询 |
| `refetchOnReconnect` | `true` | 恢复网络时自动重新获取已过期的查询 |
| 请求 `timeout` | 5 秒 | Umi request 单次请求超过 5 秒即中止 |
| 查询 `retry` | 超时最多重试 5 次 | 识别 Axios 的 `ECONNABORTED` / `ETIMEDOUT`；其他错误不自动重试 |
| 提交 `retry` | `false` | 新增、更新、删除等 mutation 默认不自动重试 |

`staleTime` 到期不会主动触发请求。需要轮询时，在具体查询上设置 `refetchInterval`；提交成功后，通过 `useQueryClient().invalidateQueries({ queryKey })` 使相关缓存失效。上述默认策略可由单个 `useQuery` / `useMutation` 覆盖。

超时重试最多 5 次，加上首次请求共最多 6 次尝试；重试等待依次为 1、2、4、8、16 秒。5 秒超时针对每次 HTTP 请求，不是整轮重试的总时间。重试规则集中在 `src/utils/requestRetry.ts`，提交操作不自动重试。直接调用 Umi request 有超时限制，但没有 React Query 的自动重试；查询函数应使用 Umi request 并将超时异常继续抛出。

全局网络提示由 `src/components/NetworkStatus/index.tsx` 实现，通过 `src/app.tsx` 的 `rootContainer` 挂载，跨页面保持监听。订阅 React Query 的 `onlineManager`，首次加载离线时同步状态；断网显示持续警告，恢复后替换为 3 秒成功提示，同一状态不重复弹出。组件卸载时取消订阅并清理自己的通知。该提示反映浏览器在线 / 离线状态，不代表后端接口、VPN 或指定域名一定可访问；接口超时仍由请求与重试策略处理。

查询的 `queryKey` 应包含分页、筛选等影响返回数据的参数。退出登录或切换账号时清理用户相关缓存；权限等要求即时更新的数据可单独设置较短的 `staleTime`。这些全局策略仅作用于 React Query，直接调用 request 或 ProTable 的独立请求不会自动获得缓存。

业务使用示例（接口地址需替换为真实地址，返回值应定义业务类型）：

```tsx
import { useQuery } from '@tanstack/react-query';
import { request } from '@umijs/max';

interface Account {
  id: string;
  name: string;
}

export function useAccounts(page: number) {
  return useQuery({
    queryKey: ['users', 'accounts', { page }],
    queryFn: ({ signal }) =>
      request<Account[]>('/实际账号接口', {
        params: { page },
        signal,
      }),
  });
}
```

参考：[Umi React Query 配置](https://umijs.org/docs/max/react-query/)、[TanStack Query 默认行为](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)。

## 六、PDF、Word、Excel 与压缩文件

| 依赖 | 用途 | 本项目的使用场景 |
| --- | --- | --- |
| `react-pdf` | 使用 React 组件显示已有 PDF | 附件预览、分页阅读；缩放和分页工具栏自行组织 |
| `@react-pdf/renderer` | 使用 React 文档组件生成 PDF | 生成报表、单据和业务报告；不是已有 PDF 的读取器 |
| `pdf-lib` | 创建或修改 PDF 文档 | 合并、拆分、添加文字或图片水印、填写 PDF 表单 |
| `exceljs` | 读取和生成 Excel 工作簿，设置单元格与样式 | 用户批量导入、账号导出、Excel 模板和报表 |
| `docx-preview` | 在浏览器中预览 `.docx` 文件 | Word 附件预览；不负责编辑或生成 Word 文件 |
| `docx` | 通过代码生成 `.docx` 文档 | 导出业务报告和格式化 Word 文档 |
| `jszip` | 读取和生成 ZIP 压缩包 | 多附件打包下载、查看 ZIP 内的文件 |

使用时注意：

- `react-pdf` 需要配置 PDF.js Worker；Worker 资源路径要适配项目的 `/framework/` 部署前缀。
- PDF 生成或处理涉及中文时，需要按所选库的要求配置中文字体。`pdf-lib` 嵌入自定义字体通常还需要额外接入 `@pdf-lib/fontkit`，它不在当前直接依赖清单中。
- `docx-preview` 的网页预览可能与 Office 排版不同；严格保真预览可由服务端转 PDF。它不支持把旧 `.doc` 文件当成 `.docx` 解析。
- ExcelJS 提供工作簿读写能力，不是可视化 Excel 编辑器，也不是完整的公式计算引擎。
- 文件上传和图片预览可使用已有 Ant Design Upload、Image；这些文档库不代替文件存储服务。
- PDF、Office、ZIP 和编辑器库优先在打开对应页面或执行操作时动态加载。大型文件可根据体积和处理耗时交给服务端。

参考：[React-PDF 预览文档](https://github.com/wojtekmaj/react-pdf)、[React-PDF 生成文档](https://react-pdf.org/)、[PDF-LIB 文档](https://pdf-lib.js.org/)、[ExcelJS 文档](https://github.com/exceljs/exceljs)、[Word 预览文档](https://github.com/VolodymyrBaydalka/docxjs)、[Word 生成文档](https://docx.js.org/)、[JSZip 文档](https://stuk.github.io/jszip/)。
