# 路径别名配置说明

项目的目录别名统一配置在 `config/config.ts`，由本地插件同步到 Umi 生成的 TypeScript 配置。

## 可用别名

| 别名            | 映射目录           | 用途                     |
| --------------- | ------------------ | ------------------------ |
| `@/*`           | `src/*`            | 源码根目录，最常用的别名 |
| `@root/*`       | 项目根目录         | 项目配置和其他根目录文件 |
| `@components/*` | `src/components/*` | 通用组件                 |
| `@pages/*`      | `src/pages/*`      | 页面组件                 |
| `@utils/*`      | `src/utils/*`      | 工具函数                 |
| `@models/*`     | `src/models/*`     | 全局状态管理             |
| `@locales/*`    | `src/locales/*`    | 国际化文件               |
| `@constants/*`  | `src/constants/*`  | 常量定义                 |
| `@public/*`     | `public/*`         | 通过 import 引用静态资源 |

类型文件使用 `@/types/xxx`。不要配置 `@types` 别名，TypeScript 会对 `@types/xxx` 导入报 `TS6137`。

## 使用示例

```typescript
import BrandSwitcher from '@components/BrandSwitcher';
import enUS from '@locales/en-US';
import { brands } from '@constants/brands';
import { trim } from '@utils/format';
```

也可以统一使用 `@/`，例如 `@/components/BrandSwitcher`。

## 配置如何生效

- `config/config.ts` 的 `alias` 负责开发和构建时的模块解析。
- `config/plugins/sync-aliases.ts` 使用 `modifyTSConfig`，将项目配置的绝对目录路径追加到生成的 `compilerOptions.paths`，保留 Umi 和其他插件提供的映射。
- 根目录 `tsconfig.json` 继承 `src/.umi/tsconfig.json`，仅设置项目的严格检查选项。

不要在根目录 `tsconfig.json` 中重新定义 `paths`：该属性会整体覆盖继承的映射，使 `@@/*`、`@umijs/max`、`@umijs/max/typings` 等失效。生成的 `.umi` 文件由 Umi 管理，不要手动修改。

## 添加新别名

只需在 `config/config.ts` 的 `alias` 中添加目录映射。例如：

```typescript
alias: {
  '@hooks': join(__dirname, '../src/hooks'),
  // ... 其他别名
},
```

创建对应目录后，执行以下命令更新生成的配置并检查类型：

```bash
pnpm setup
pnpm typecheck
```

正在运行的开发服务需重新启动，使模块解析配置同步更新。编辑器仍显示旧错误时，重启 TypeScript 服务。

## 静态资源路径

`@public` 用于模块导入，不会替换 HTML 或 JSX 中的字符串 URL。直接引用 `public/logo.svg` 时，仍使用项目部署前缀：

```tsx
<img src="/framework/logo.svg" alt="Logo" />
```
