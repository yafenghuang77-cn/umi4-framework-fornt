# 性能统计与监控

## 查看统计

启动项目后，展开 **性能统计** 目录菜单：

- **统计概览**（`/framework/monitoring/overview`）：独立图表页面，包含可切换指标的每日 P50/P75/P95 趋势、良好参考线、体验分布环图、页面 P75 Top 10 排行、接口与异常趋势。按日期、页面、版本筛选，空样本留断点，不填充演示值。图表使用 ECharts SVG 渲染，支持响应式尺寸和文字描述。
- **数据查询**（`/framework/monitoring/query`）：采集明细表、性能聚合表、日志异常表和每日上报表；明细支持类型和指标筛选，展开行可查看上下文，支持 JSON 导出。

访问 `/framework/monitoring` 自动跳转统计概览。两页共用数据源和查询逻辑。

默认不需要 Sentry 账号或统计后端：浏览业务页面、操作按钮或预览文件后即可查看**当前浏览器真实采集的数据**。页面展示采集量、异常量、每日趋势、P50/P75/P95、Web Vitals 良好占比、日志与日报状态，支持日期/页面筛选、手动刷新、暂停自动刷新及 JSON 导出。

- 日期按北京时间（Asia/Shanghai）统计。
- 本地数据在 IndexedDB `framework-monitoring-v1` 中，刷新后保留；不同浏览器、域名、端口之间隔离。
- 最多保留 30 天 / 10,000 条明细，定时清理；此范围是本地留存窗口，不代表全量长期数据。高流量场景应接服务端。
- 存储不可用时降级为内存，并在页面提示；关闭页面后内存数据丢失。
- 无数据时显示空状态，不生成演示数据。未采集到的指标不会补零。
- 自动刷新间隔 10 秒，隐藏的统计页暂停刷新；采集和上报任务独立运行。
- 当前浏览器的统计、服务端查询结果有明确来源提示；查询失败不会混用本地数据。
- “每日上报”按自然日汇总，不受页面筛选影响；导出遵循当前日期与页面筛选（日报仍为整日）。

## 配置

参考根目录 `.env.monitoring.example`，把需要的配置写入对应环境的本地覆盖文件，例如 `.env.dev.local`：

```dotenv
MONITORING_ENABLED=true
SENTRY_DSN=https://PUBLIC_KEY@SENTRY_HOST/PROJECT_ID
SENTRY_TRACES_SAMPLE_RATE=0.1
APP_RELEASE=frontend@2026.10.14.1
MONITORING_INGEST_URL=/api/monitoring/ingest
MONITORING_QUERY_URL=/api/monitoring/query
```

所有配置都可省略。DSN 和接口默认留空，只采集本地数据，不向任何预设第三方地址上报。配置变更后须重启开发服务或重新构建；`.env.monitoring.example` 不会自动加载。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `MONITORING_ENABLED` | `true` | `false` 禁用采集与上报，历史数据仍可查看 |
| `SENTRY_DSN` | 空 | Sentry 项目的公开 DSN；有值后初始化 SDK |
| `SENTRY_TRACES_SAMPLE_RATE` | `0.1` | Sentry 性能追踪采样率，限制在 0–1；不控制本地采集或日志采集 |
| `APP_RELEASE` | `local` | 发布版本，建议 CI 使用版本号或提交 SHA，线上必须按发布更新 |
| `MONITORING_INGEST_URL` | 空 | 自建监控上报接口，支持明细与日报 |
| `MONITORING_QUERY_URL` | 空 | 项目统计页的服务端数据查询接口 |

环境名复用项目的 `APP_ENV`（dev/uat/pre/prod），数据分环境展示。配置通过 `config/config.ts` 的 `MONITORING_CONFIG` 白名单注入浏览器；不要放 Sentry auth token、服务端管理密钥。Sentry DSN 只负责数据写入，不具备数据查询权限。

## Sentry 性能、异常与日志

使用已有的 `@sentry/react` **11.x** API，在 `src/app.tsx` 中尽早、仅一次初始化：

- `browserTracingIntegration()`：首次加载、History 路由导航、fetch/XHR 请求与浏览器支持的性能指标。
- `consoleLoggingIntegration()`：将 `console.warn` / `console.error` 发送到 Sentry Logs，不批量采集普通 console.log。
- `monitoringLog()`：显式的 debug/info/warn/error 结构化日志。
- `captureError()`：业务异常上报；统一请求错误入口已经接入，跳过全局提示也仍会记录。
- 根部 `ErrorBoundary`：捕获 React 渲染异常，提供刷新入口。
- 全局 error/unhandledrejection：本地保存异常摘要，Sentry 启用时 SDK 负责对应异常上报。
- 自定义业务耗时对应 Sentry `ui.business` span。

SDK 11 的日志默认开启，使用 `dataCollection` 逐项关闭用户信息、Cookie、HTTP 头、请求响应体、URL 参数和栈局部变量采集；未使用旧版 `enableLogs` / `sendDefaultPii` 配置。

```ts
import { captureError, monitoringLog } from '@/utils/monitoring';

monitoringLog('info', 'orders.search.completed', { count: 20, cacheHit: true });
monitoringLog('warn', 'orders.search.slow', { duration: 3200 });
captureError(new Error('订单查询失败'), { source: 'orders' });
```

配置 DSN 后，可在 Sentry 项目中按 `environment` / `release` 查询 Traces、Issues 和 Logs。日报日志名为 `performance.daily`（总量）和 `performance.daily.metric`（分组分位数），可按 `report_id` / `revision` 关联。日报自身不会再次写入本地日志形成循环统计。

本地统计页面不会用 DSN 直接读取 Sentry。Sentry 数据读取需要服务端保存查询凭证并提供查询接口；不得把 Sentry 查询 token 放到前端。

发布产物当前关闭 sourcemap，Sentry 能接收错误但压缩后的堆栈定位受限。需要源码定位时，在 CI 中私下生成并上传 sourcemap 后再移除，不把源码映射公开部署。此项目没有预设组织、项目或上传令牌。

## web-vitals 与统计口径

显式依赖 `web-vitals`，一次注册 `onLCP` / `onINP` / `onCLS` / `onFCP` / `onTTFB`。

| 指标 | 含义             | 单位   | 良好参考           |
| ---- | ---------------- | ------ | ------------------ |
| LCP  | 最大内容绘制     | ms     | ≤ 2500             |
| INP  | 交互到下一次绘制 | ms     | ≤ 200              |
| CLS  | 累计布局偏移     | 无量纲 | ≤ 0.1              |
| FCP  | 首次内容绘制     | ms     | 以库的 rating 为准 |
| TTFB | 文档首字节响应   | ms     | 以库的 rating 为准 |

指标按文档访问生命周期采集，保留初始页面归属；SPA 切换时不会重新注册观察器，也不会把旧页面延迟回调错误归到当前路由。相同 `metric.id` 使用 IndexedDB put 更新原样本，不把多个累计值作为独立样本。使用指标最终 value，不累加 value。未开启实验性的软导航统计，因此不同浏览器保持同一统计口径。

INP 需要用户交互；LCP/CLS/INP 可能在交互或页面进入后台后才回调，没有立即出现不代表采集失败。页面关闭时浏览器不保证异步 IndexedDB 写入或上传完成，下一次打开只能补报已经持久化的数据。

P50/P75/P95 使用 nearest-rank，按页面、指标、版本分组。Web Vitals 良好占比来自库的 rating；不同单位不会混算。样本量小的分位数只供观察。Sentry 的采样追踪与本地 Web Vitals 是不同的数据管道，不应把两个来源相加当作独立访问数。

`ROUTE_PAINT_ESTIMATE` 是 Umi 路由通知后到双 requestAnimationFrame 的估算等待，只对可见页面记录。它不包含通知前的懒加载，不保证业务数据或像素已经渲染，不应称作页面可用耗时。

### 业务可用耗时

使用 `startMeasure`，在实际业务开始时计时，并在关键内容真正可用的回调结束：

```ts
import { startMeasure } from '@/utils/monitoring';

const finish = startMeasure('USERS_READY');
// 请求结束后仍需等待列表实际提交或组件提供的渲染完成回调。
// 成功显示内容后：
finish('success');
// 失败 / 用户退出时分别使用 finish('error') / finish('cancelled')。
```

结束函数幂等，保留开始时的页面访问归属。失败/取消的 measure 保留在明细中，但不混入成功耗时分位数。业务代码必须主动调用结束函数，框架不会把组件挂载当作页面可用。

文件预览已接入 `PREVIEW_DOWNLOAD` 和通用 `PREVIEW_PARSE_<类型>`。解析耗时覆盖 `usePreview` 的 loader，不等于 PDF 首屏或 iframe 完成显示；这些渲染时刻应按具体组件回调再接 `startMeasure`。不上传文件名、文件内容或下载链接参数。

### 请求耗时

Umi request 拦截器记录每次网络请求的起止、方法、归一化路径、HTTP 状态和失败标记。业务失败（HTTP 200 但 success=false 或未登录业务码）也标记失败。网络失败状态记 0。

每次重试是独立请求样本。React Query 缓存命中不会产生网络样本；这里的耗时不包含重试退避和全部用户等待时间，整体等待需业务 measure 补充。主动取消不会经过错误上报入口，但可能留下已取消网络请求耗时。

## 每日汇总与可靠性

1. 每次打开页面约 1 秒后检查一次；页面运行时每分钟检查；网络恢复或回到前台时补查。
2. 以北京时间划分自然日，今天不提前生成最终日报；次日首次检查生成前一天日报，离线多天后重开按日期补报留存窗口内的数据。
3. 日报 ID 为 `<浏览器ID>:<环境>:<日期>`。同一 ID 的 revision 随样本更新变化，晚到的旧日指标会更正日报。
4. 同一标签页只运行一个上报任务，支持 Web Locks 的浏览器还会跨标签页互斥；服务端仍须幂等，不能依赖浏览器锁实现 exactly-once。
5. 配置自建接口时，优先发日报到该接口；否则向 Sentry Logs 提交日报；都未配置时保留 pending。
6. 原始明细只在配置自建接口后发送，每轮最多 100 条，失败保留，下轮重试。Sentry 的自动追踪/日志由 SDK 自行发送。
7. 网页关闭期间不会运行计时器。需要每天固定时间生成全站报表或消息推送时，后端应根据已入库明细部署定时任务。当前实现不创建 Codex 自动化或操作系统定时任务。

| 状态              | 含义                                                           |
| ----------------- | -------------------------------------------------------------- |
| 待上报            | 无目标、离线或上传失败，保留用于重试                           |
| 接口已确认        | 自建接口返回 2xx JSON `{ "accepted": true }`                   |
| 已提交 Sentry SDK | SDK flush 完成队列处理；不等同于 Sentry 服务端成功入库或可查询 |

上报失败不会阻断业务，不进入业务请求拦截器，不递归上报监控接口错误。独立 fetch 超时 10 秒，仅同源携带 Cookie；跨域默认不携带凭证。后端若要求 Bearer Token，应通过受控的 transport 适配接入，不要把固定密钥写入构建变量。

## 后端接口约定

完整 TypeScript 类型位于 `src/utils/monitoring/types.ts`。接口属于待实现后端契约，项目未包含虚构的线上服务或模拟成功接口。

### POST 上报

配置 `MONITORING_INGEST_URL`。Content-Type 为 `application/json`，有两种 payload。

明细批次：

```json
{
  "type": "events",
  "events": [
    {
      "id": "vital:v6-example-LCP",
      "visitId": "uuid",
      "timestamp": 1791939600000,
      "updatedAt": 1791939601000,
      "environment": "prod",
      "release": "frontend@1.0.0",
      "route": "/framework/welcome",
      "kind": "vital",
      "name": "LCP",
      "value": 1200,
      "unit": "ms",
      "rating": "good"
    }
  ]
}
```

服务端按 `id` upsert，并拒绝用较旧 `updatedAt` 覆盖新值；`uploadedAt` 为客户端队列元数据，不作为统计时间。必须在整批验证、可靠入库后返回成功；部分写入时要允许整批幂等重试。不要因为重复 ID 拒绝整个请求。

日报：

```json
{
  "type": "daily",
  "report": {
    "id": "browser-id:prod:2026-10-14",
    "revision": "content-revision",
    "date": "2026-10-14",
    "environment": "prod",
    "generatedAt": 1791993601000,
    "eventCount": 80,
    "logCount": 5,
    "errorCount": 1,
    "metrics": [
      {
        "key": "group-key",
        "route": "/framework/welcome",
        "name": "LCP",
        "release": "frontend@1.0.0",
        "unit": "ms",
        "count": 20,
        "p50": 1100,
        "p75": 1500,
        "p95": 2300,
        "goodRate": 0.95
      }
    ],
    "status": "pending"
  }
}
```

服务端按 report.id 保存快照、按 revision 去重；更新时替换旧快照，不能累加多次提交的 count。客户端状态字段不代表服务端事实。日报只是该浏览器留存样本的摘要，**全站 P75/P95 必须从去重明细或可合并的分位数结构计算，不能平均各浏览器的分位数**。

成功响应固定为：

```json
{ "accepted": true }
```

推荐不合法请求用 400、未授权 401/403、限流 429、服务异常 5xx。返回 HTML（例如 Nginx SPA 回退）或 `{ accepted: false }` 不会被视作成功。

### GET 查询

配置 `MONITORING_QUERY_URL`，前端请求：

```text
GET /api/monitoring/query?from=2026-10-08&to=2026-10-14&environment=prod
```

`from/to` 都是含首尾的北京时间自然日，返回 JSON **直接对象**，不包在业务 data 字段中：

```json
{ "events": [], "reports": [] }
```

events 是去重后的 MonitoringEvent 数组；reports 是 DailyReport 数组。日报展示状态由后端按确认事实提供。前端在结果上按页面和版本计算分位数；单次最多查询 30 天，每个返回数组最多 10,000 条，超限会提示错误而非截断。后端应保证此查询范围完整，不能静默截断或返回抽样却标成全量。数据量过大时应返回清晰错误，并扩展分页/服务端聚合协议后再开放大范围查询。

查询接口必须由后端做身份验证、环境和组织访问控制、限流、字段校验。当前项目的菜单/路由和现有用户管理一样未提供生产级权限控制；不要将跨用户日志直接开放给任意访客。跨域需正确配置 CORS；推荐由同源网关提供接口。

## 隐私、边界与验证

- 路径去掉查询参数和 hash，数值 ID、UUID、长随机标识归一化；已知敏感字段、Bearer 值和邮箱脱敏。
- 这是基础脱敏，不保证任意自由文本都无敏感内容；调用方仅传受控消息与允许的业务属性。
- 不启用 Session Replay，不采集文件内容，不记录原始 Axios config 或响应体。
- 日报提交与明细上传都使用重试和幂等，不承诺离线终端、清理浏览器存储或最后一刻关闭页面时不丢数据。
- 本地留存受容量限制；用于全站长期统计必须配置服务端，不能把本地数据当成全站访问情况。

```bash
pnpm typecheck
pnpm test -- --runInBand
pnpm exec playwright test tests/e2e/monitoring.spec.ts
```

单元测试覆盖时区、分位数、取消过滤、脱敏、稳定指标 ID、日报失败/重试/更正/并发与环境隔离。浏览器测试覆盖真实采集、IndexedDB 刷新持久化、日志脱敏、JSON 导出、日报待上报及小屏布局。使用真实 DSN/接口的端到端入库验证需要部署服务后执行；未配置目标时不会声称已验证远端接收。
